Visión general

El dashboard de HidroSSO es el portal de entrada al ecosistema hidroBIntel. Cada app del ecosistema Hidrobart aparece como una tarjeta navegable. El sistema es paramétrico: las apps se definen en un archivo JSON externo, no en el código del componente.

La arquitectura de archivos es la siguiente:

frontend/
├── app/
│ └── dashboard/
│ │ └── page.tsx ← Componente principal (lee apps.json)
│ └── dashboardFirst/
│ └── page.tsx ← Backup del dashboard anterior
└── data/
└── apps.json ← Fuente de verdad de las apps
2

Schema — apps.json

Cada entrada del array representa una app del ecosistema. Todos los campos son requeridos.

Campo Tipo Req. Descripción
idstring✅Identificador único. Usado para mapear el gradiente del ícono.
namestring✅Nombre visible en la tarjeta.
substring✅Dominio mostrado debajo del nombre.
descstring✅Descripción corta de la app.
iconstring✅Emoji que representa la app.
urlstring✅URL de destino. Usar "#" si no hay URL aún.
tagstring✅Badge de estado. Vacío "" o uno de los valores permitidos.
ssoIdstring | null✅null = link directo. string = lanza flujo SSO con ese ID.
activeboolean✅true = app activa. false = aparece en sección Legado/Deprecado.
tier"public" | "team" | "admin"✅Nivel de visibilidad según orgRole de Azure AD.
ordernumber✅Orden de aparición en el grid (ascendente).

Valores permitidos para tag

ACTUALIZADO Verde — App recientemente actualizada
NUEVO Azul — App recién incorporada
PROTOTIPO Amarillo — En desarrollo, no production-ready
IDEA Púrpura — Concepto, sin desarrollo real

Ejemplo completo de entrada

{
  "id":     "costeo",
  "name":   "Costeo360",
  "sub":    "costeo360.hidrobart.com",
  "desc":   "Costeo Hidrobart",
  "icon":   "💰",
  "url":    "https://costeo360.hidrobart.com",
  "tag":    "ACTUALIZADO",
  "ssoId":  "costeo360",
  "active": true,
  "tier":   "public",
  "order":  5
}

Lógica del componente

function canSee(app: App, orgRoles: string[]): boolean {
  if (app.tier === "public") return true;
  if (app.tier === "team")   return orgRoles.some(r => ["Manager","Admin","SuperAdmin"].includes(r));
  if (app.tier === "admin")  return orgRoles.some(r => ["Admin","SuperAdmin"].includes(r));
  return true;
}

Sistema SSO

Las apps con ssoId no abren una URL directamente — lanzan el flujo SSO del backend, que genera un token de sesión temporal para la app destino.

1
Click en tarjeta SSO
Usuario hace click en una app con ssoId (ej: "costeo360")
2
Llamada al Next.js API Route
GET /api/sso-launch?app={ssoId}
3
Backend genera token temporal
FastAPI /auth/sso-launch → token UUID → almacenado en Redis (TTL 60s)
4
Respuesta con redirect_url
{ redirect_url: "https://costeo360.hidrobart.com/auth/sso?token=..." }
5
Abre app destino
window.open(redirect_url, "_blank") → app destino intercambia token → sesión activa

How-to

Agregar una nueva app

1
Abrir frontend/data/apps.json
2
Agregar una nueva entrada siguiendo el schema de la sección 2. Asignar un id único (snake_case, sin guiones).
3
Agregar el gradiente del ícono en ICON_GRADIENT dentro de page.tsx: 
miapp: "linear-gradient(135deg, #COLOR1 0%, #COLOR2 100%)",
4
Commit + push desde VS Code local → git pull en VM → npm run build → pm2 restart hidrosso-frontend
⚠️
Fase 2 (futuro): Cuando el JSON se mueva al backend FastAPI (GET /config/apps), solo será necesario editar el JSON en el servidor — sin rebuild.

Promover una app a tier más amplio

Cuando una app en admin o team esté lista para más usuarios, solo editar el JSON:

// Antes — solo admins la ven
{ "tier": "admin", "tag": "PROTOTIPO" }

// Después — todos la ven
{ "tier": "public", "tag": "ACTUALIZADO" }
✅
Solo editar el JSON + commit + deploy. Sin cambios en código.
