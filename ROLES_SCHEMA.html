Flujo de Autenticación y Roles

1
Login en HidroSSO con Microsoft 365 El usuario se autentica una sola vez con su cuenta @hidrobart.com
2
Backend consulta Azure AD Graph API Obtiene perfil de usuario + grupos (ej: HB-SuperAdmin)
3
Mapeo de grupos → OrgRole "HB-SuperAdmin" contiene "superadmin" → OrgRole: SuperAdmin
4
Sesión creada en Redis (8h TTL) Contiene: user_id, email, tenant, roles { org, functional, process }
5
Usuario hace clic en app (ej: Costeo360) /api/sso-launch genera launch token de 60 segundos, un solo uso
6
Costeo360 canjea el token /api/sso-entry → /auth/sso-exchange → recibe session_id → setea cookie hidrosso_sid
7
Costeo360 obtiene roles vía /auth/session-info Recibe roles.org, roles.functional, roles.process y aplica permisos en UI

Implementación en Apps (TypeScript)

// 1. Obtener roles del usuario desde HidroSSO
const res = await fetch(`${HIDROSSO_API}/auth/session-info`, {
  headers: { Cookie: `hidrosso_sid=${sessionId}` }
});
const { roles } = await res.json();

// 2. Verificar OrgRole
const isSuperAdmin = roles.org.includes("SuperAdmin");
const isAdmin      = isSuperAdmin || roles.org.includes("Admin");
const isManager    = isAdmin || roles.org.includes("Manager");

// 3. Verificar permiso en módulo específico
const canApprove  = (mod: string) => roles.process[mod]?.includes("aprobar")    ?? false;
const canConfigure = (mod: string) => roles.process[mod]?.includes("configurar") ?? false;
const canWrite    = (mod: string) => roles.process[mod]?.includes("escribir")   ?? false;
